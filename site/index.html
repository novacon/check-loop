01 / What you get 4 skills

what you get

Your session model is the orchestrator. It runs the workflow and opens every cited source before acting on a finding. Codex reviews in a read-only sandbox.

Plan

Review a plan

One broad review, then later rounds check only the fixes. Six rounds by default, or one pass with --quick. Picks up where it left off if interrupted.

● ● ●claude code
/check-loop path/to/plan.md
Research

Research a question

Writes a sourced draft and Codex checks it. You get one Markdown report with sources and open questions. No code.

● ● ●claude code
/check-loop:research "question"
Execute

Execute a plan

The runner snapshots the tree before each step, without staging. A fresh subagent builds the step, your checks run, and Codex reviews the diff since the snapshot. A step gets three fix attempts. Nothing is committed or pushed without your approval.

● ● ●claude code
/check-loop:execute path/to/plan.md
Settings

Pick the reviewer

Set the Codex model, effort, round limit and implementer model, for all projects or just one. Unset values use your Codex and session defaults.

● ● ●claude code
/check-loop:settings

02 / Watch it run 3 skills

watch it run

Codex raises findings with citations. The orchestrator opens each cited line, then accepts, rejects or counters. You see one summary line per round.

● ● ●claude code

Example runs. Summary lines and outcomes use the plugin's real output format; the plans, files and findings are illustrative.

03 / How it decides One finding

how it decides

Every finding cites a source and carries an evidence label. Only findings the orchestrator has verified can block.

InCodex raises a finding

01 The orchestrator checks the citation

VERIFIED, critical or important→Blocks until accepted, rejected or countered
INFERENCE or UNVERIFIED→Report only
Minor, or a question→Report only

02 The next round diff only

Regression, or a missed critical defect→Can still block
Repeat of a decided finding→Dropped
● ● ●evidence labels
VERIFIED    the cited source supports the claim
INFERENCE   suggested by the source, not reproduced
UNVERIFIED  evidence missing or inaccessible

A failure is never approval

A failed, empty or timed-out review is retried once, then the run stops. If blockers stall or the round limit is reached, you decide what happens next.

Secrets are redacted from everything Codex is sent, and step reviews omit .env, secret and credential files. Codex can still read the checkout, so keep secrets in ignored paths.

04 / Install 4 steps

install it

You need Node.js 18+ and a signed-in Codex CLI. For pi, see the quick start.

STEP 1

Check your version

Claude Code 2.1.257 or later.

● ● ●shell
claude --version

STEP 2

Sign in to Codex

Headless? Use codex login --device-auth.

● ● ●shell
npm install -g @openai/codex
codex login

STEP 3

Install the plugin

Inside Claude Code.

● ● ●claude code
/plugin marketplace add Novacon/check-loop
/plugin install check-loop@lordknows13-check-loop
/reload-plugins

STEP 4

Pick your model

The skills don't switch models, so start on the one you want.

● ● ●shell
claude --model fable

Status: ready

codex-invoke.mjs setup confirms Codex is installed and signed in, not model access.

Wrong reviewer

Unsupported or mismatched settings fail. It never swaps reviewers silently.

Uncommitted work

execute asks first: use a separate worktree, or include your changes.

Update

/plugin marketplace update lordknows13-check-loop, then /plugin update check-loop@lordknows13-check-loop. Settings carry over.

05 / Settings /check-loop:settings

tune it

Each setting uses the first value it finds: CLI flag, then .claude/check-loop.json, then ~/.claude/check-loop/config.json, then the default.

SettingDefaultWhat it changes
modelyour Codex configCodex reviewer model ID, or default.
effortyour Codex configReviewer reasoning effort, or default.
maxRounds6Plan and research round limit, 1 to 40.
implementerModelyour session modelSubagent model for execute, such as opus or a pi provider/id.

From the CLI

node plugins/check-loop/scripts/codex-invoke.mjs config --project --effort high

What's new in 5.2.1

Step snapshots reuse git's index cache, so recording a 20,000-file tree takes about 50 ms instead of 2 seconds. 5.2 moved execution review into code and replaced the shared broker with one codex app-server per command.

Develop

The loop lives in scripts/lib/review-loop.mjs. node --test tests/ runs without model access.
